## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Project rules
- Explicitly track (`git add -f`) sources under any `logs/` directory — `src/lib/logs/` (parser, tests, metadata) and `src/routes/api/*/logs/` (ingestion API routes) — despite the managed `logs` ignore pattern, so clean builds include these source dependencies.
- Server functions live in `src/lib/api/*.functions.ts` (not `src/server/`, which import-protection blocks from client code).
- Log parsing is pure TS in `src/lib/logs/parsers.ts`, run server-side on ingest and client-side only for previews; missing source fields stay null. Covered by `parsers.test.ts`.
- Tenant isolation: every app table has `org_id` with RLS via `is_org_member` / `can_write_org`; aggregates go through SECURITY DEFINER RPCs that check membership.
- Demo data is generated by `load_demo_data` RPC and flagged `is_demo` so it can be removed without touching real data.
- Upload completion awaits an organization-scoped history refetch before finishing; broad cache invalidation must not race the history request.
- Ingestion API lives at `/api/v1/*` (aliases under `/api/public/v1/*` for private published sites); handlers call `src/lib/ingest/handler.server.ts`, which derives the tenant only from the hashed API key (plaintext keys are never stored). Pure validation/auth logic stays in `src/lib/ingest/core.ts` with unit tests.
- Collectors use Fluent Bit plus the loopback Python adapter with a durable SQLite spool and the existing ingestion API; this bridges Fluent Bit arrays to bounded authenticated envelopes without a parallel external API.
- Collector configuration writes go through an admin-authorized server function and database binding trigger; generated files contain no credentials and heartbeat is sent only after probing the real Fluent Bit health endpoint.
- Collector delivery counters update atomically through a service-only RPC, while API batch completion evaluates existing alert rules through a database trigger; membership-checked hourly RPCs preserve tenant isolation.
